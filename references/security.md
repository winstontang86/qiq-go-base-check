# Web、业务与权限安全检查

仅执行防御性代码审查和授权测试。沿“输入来源 → 校验/鉴权 → 敏感操作 → 返回/日志”阅读真实调用链，检视受影响入口及可绕过路径；不把关键词扫描或单个安全库的存在当作通过。

## 4.1 常见后台 Web 与业务安全

| 风险 | 审查要点与通过证据 |
| --- | --- |
| SQL 注入 | 使用参数绑定而非拼接输入；动态表名/列名/排序字段使用固定映射或允许列表，不能用值占位符替代标识符校验；检查 ORM raw/表达式和批量查询。沿输入到执行点确认绑定，不能仅依靠输入过滤。 |
| 任意文件上传 | 检查服务端类型/大小/数量限制、内容格式验证、文件名规范化、路径穿越与符号链接、覆盖风险；隔离可执行目录并禁止执行，授权下载和对象归属；文件名/扩展名及客户端 Content-Type 不能单独作为可信类型证明。 |
| SSRF | 检查用户可控 URL/host/协议/端口和代理；仅允许业务必需目标与协议，解析并验证全部 IPv4/IPv6 地址；阻止 loopback、私网、link-local、云元数据及环境要求的额外网段（9/10/11/21/30.*）；校验重定向、DNS rebinding、IPv4-mapped IPv6，确保校验目标与实际连接一致。确需内网访问时取得明确授权并使用限定目的地允许列表，不放开任意内网。 |
| 反序列化 | 对不可信数据采用安全解析模式，不加载任意类型或执行对象构造；限制大小、嵌套深度及资源使用。安全模式不等同于“所有字段都可可信使用”。 |
| 敏感信息泄露 | 检查 API、错误、日志、调试接口、配置和监控；不暴露栈、绝对路径、源码、内部连接串、密钥或超出授权的数据。密码采用适合密码的带盐强哈希；密钥来自环境/受控密钥管理，不写入源码或报告。 |
| 业务逻辑 | 金额/价格/角色/状态由服务端可信来源确定；密码重置身份与对象绑定、一次性与时效；验证码限制次数/速率、用途绑定、过期且不可复用；检查支付回调签名、防重放、幂等及状态机。 |
| 命令注入/RCE | 尽量不执行系统命令；必须执行时使用固定程序与参数数组、限制参数语义和路径，避免 shell/eval；检查选项注入、可控环境变量、可执行文件搜索路径与模板表达式。 |
| XSS | 对管理后台、HTML/模板/邮件等按输出上下文转义，限制富文本和危险 URL 协议；JSON 编码不能代替所有 HTML/JS 上下文转义。 |
| CSRF/CORS | Cookie 认证的状态变更接口具备 CSRF 防护或等价可验证约束；CORS 按必要来源限定，不允许任意来源带凭据，不以 CORS 替代认证。 |
| 资源与输入边界 | 检查请求体/分页/批量数量、解压、正则、文件大小、限流、超时和取消；避免输入触发可重复的资源耗尽。 |

## 4.2 权限、越权与访问控制

- **未授权访问**：核查所有受影响路由、RPC、异步入口和后台任务的认证边界；确保异常和默认分支拒绝访问，未登录/过期凭据不能访问敏感 API。
- **水平越权 / IDOR**：对读取、修改、删除、导出、批量操作和文件下载校验资源所属用户/租户。对象 ID 难猜或 UUID 不能替代所有权校验；不能只信任请求中的 user/tenant ID。
- **垂直越权**：在后端对具体操作做权限/角色校验；普通管理员不能直接调用高权限接口；角色变更、自我授权、权限缓存撤销保持正确。
- **前端控权**：隐藏按钮、菜单、页面入口不是授权；验证后端 handler/service 的二次校验及替代路由。
- **统一中间件**：验证路由确实挂载，排除旁路、白名单过宽、内部接口裸露、GraphQL/RPC 单独入口和异步复用的越权风险。
- **多租户**：查询/更新/缓存键/消息/导出都保持租户边界；批量处理逐资源验证，不仅校验首项。

## 4.3 Token / Session

- 核查签名算法允许列表与签名验证，不接受未签名或可替换算法；验证 issuer、audience、exp、必要的 nbf 及用途。
- 检查短期访问凭据、refresh token 轮换/撤销/复用检测、退出和权限变化后的失效，不将长期明文凭据存入日志或 URL。
- 检查 session fixation、防会话劫持、Cookie 的 Secure/HttpOnly/SameSite 与实际跨域业务；Token 认证不自动免除所有重放和权限撤销问题。
- 检查随机性、密钥来源和权限最小化；使用受控测试凭据，不打印真实 Token。

## 判定与记录

- 为适用的每类风险记录入口、数据流、实际防护及证据；对不适用类别写原因，不要求每个改动都新增所有防护。
- 对受影响链路中已确认的安全漏洞，不论本次引入/加剧还是存量、不论是否已被利用，记 `FAIL` 并阻断；无关存量问题仅提醒。受影响关键授权边界无法确认时记 `UNKNOWN`。
- 同时记录必要的安全回归用例：未登录、同级不同用户/租户、低权限角色、无效/过期凭据、危险输入等。避免只测试正确权限的成功路径。
- 不在报告复制敏感数据或可直接用于攻击现网的载荷；采用脱敏路径、参数名和防御性复现条件。
